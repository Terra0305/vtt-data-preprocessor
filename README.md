# VTT Subtitle OCR Cleaner

OCR로 추출한 영어/한국어 VTT 자막 파일을 1차 정제하기 위해 만든 Python 스크립트입니다.

GIST 의뢰 자막 데이터 정제 작업에서 사용했던 코드를 포트폴리오 공개용으로 정리한 버전입니다. 실제 데이터셋 이름, 파일 경로, 일부 작업 정보는 보안상 일반화했습니다.

이 프로젝트의 목적은 자막 내용을 완전히 자동으로 검수하거나 번역 매칭을 끝내는 것이 아니라, OCR 과정에서 반복적으로 발생하는 오탈자와 자막 노이즈를 먼저 줄여 이후 수작업 검수 부담을 낮추는 것이었습니다.

## 작업 배경

OCR로 생성된 자막 파일에는 같은 오류가 반복해서 나타나는 경우가 많았습니다.

예를 들면 영어 자막에서는 `dont`, `cant`, `youre`처럼 apostrophe가 빠진 표현이 반복됐고, 한국어 자막에서도 특정 단어가 잘못 인식되는 경우가 있었습니다. 또 `[BGM]`, `(웃음)`, `♪`, `#`처럼 분석 대상 대사가 아닌 텍스트도 섞여 있었습니다.

이런 항목을 매번 직접 수정하면 시간이 많이 들기 때문에, 반복 규칙으로 처리할 수 있는 부분을 Python 스크립트로 분리했습니다.

## 주요 기능

- VTT 파일의 타임스탬프, 번호, `WEBVTT` 헤더는 유지
- 대사 줄에 포함된 `[]`, `()` 안의 부가 정보 제거
- `#`, `♪`, `&` 등 불필요한 특수문자 제거
- CSV 파일에 등록한 오탈자 규칙을 기준으로 텍스트 치환
- 영어/한국어 자막 파일을 같은 방식으로 일괄 처리
- 처리 과정과 오류를 로그로 기록

## 하지 않는 것

이 스크립트는 영어/한국어 자막의 의미적 1:1 매칭을 자동으로 판단하지 않습니다.

번역 자막은 어순이 다르거나 한 문장이 여러 블록으로 나뉘는 경우가 있어, 단순 규칙만으로 정확한 대응 관계를 판단하기 어렵습니다. 이 코드는 그런 검수 전에 반복 오류와 노이즈를 줄이는 1차 전처리 단계로 사용했습니다.

## 파일 구성

```text
.
├── All-in-One_nda.Ver.py    # 전처리 스크립트
├── typos.csv                # 반복 오탈자 교정 규칙 예시
├── Command                  # 작업 당시 정리한 요구사항 메모
└── README.md
```

## 교정 규칙 예시

`typos.csv`는 아래와 같은 형태로 관리합니다.

```csv
typo,correction
cant,can't
dont,don't
혹여래도,혹여라도
```

작업 중 반복적으로 발견한 OCR 오류를 CSV에 추가한 뒤 스크립트를 다시 실행하면, 같은 오류를 한 번에 교정할 수 있습니다.

## 사용 방법

스크립트 상단의 설정값을 처리할 파일명과 폴더 구조에 맞게 수정합니다.

```python
TARGET_FILE_NAME = "sample_dataset_v01"
INPUT_DIR = "raw_data"
OUTPUT_DIR = "cleaned_data"
TYPO_DICT_FILE = "typos.csv"
```

입력 파일은 아래 이름 규칙을 기준으로 찾습니다.

```text
raw_data/
├── sample_dataset_v01_en.vtt
└── sample_dataset_v01_kr.vtt
```

실행:

```bash
python All-in-One_nda.Ver.py
```

처리 결과는 `cleaned_data` 폴더에 저장됩니다.

```text
cleaned_data/
├── sample_dataset_v01_en_CLEANED.vtt
└── sample_dataset_v01_kr_CLEANED.vtt
```

## 회고

처음에는 모든 자막 정제를 자동화하려고 했지만, 영어/한국어 번역 자막의 1:1 대응은 단순 규칙만으로 처리하기 어려웠습니다. 그래서 코드로 안정적으로 줄일 수 있는 반복 오류와 노이즈 제거에 범위를 맞췄고, 이후 사람이 확인해야 하는 구간을 줄이는 방향으로 사용했습니다.
